## Chapter II

### Jetpack Compose

Библиотека, предоставляющая современный набор инструментов для создания Android UI. Jetpack Compose упрощает и ускоряет написание Android UI, предоставляя возможность описать интерфейс с помощью функций, которые написаны на языке Kotlin.

### Box

Компонент библиотеки Jetpack Compose, простейший контейнер других компонентов. Компонент Box является некоторой областью экрана и может использоваться без вложенного в него содержимого.

### Column

Компонент библиотеки Jetpack Compose, контейнер, который способен выстроить вложенные в него компонентны в столбец.
Важная особенность Column — это возможность задать вложенным в него компонентам вес. Вес вложенных компонентов отвечает за высоту, которую будет занимать соответствующий компонент.

### Row

Компонент библиотеки Jetpack Compose, контейнер, который способен выстроить вложенные в него компонентны в строку.
Схож с Column в том, что можно задать вес вложенным компонентам. Отличается от Column тем, что вес вложенных компонентов отвечает за ширину, которую будет занимать соответствующий компонент.

### Modifier

Коллекция, хранящая функции, которые задают внешний вид компонента путем изменения значений атрибутов данного компонента. К одному и тому же компоненту можно применить сколько угодно модификаторов.

### LaunchedEffect

Функция, позволяющая запустить корутину внутри области видимости Composable-компонента.
LaunchedEffect запускает корутину тогда, когда компонент попадает в область видимости Composable-функции и завершает выполнение корутины, когда компонент покидает область видимости Composable-функции.
Если произойдет рекомпозиция LaunchedEffect с другими параметрами, то существующая корутина будет завершена, а LaunchedEffect запустит новую.

### Animation

Анимации в приложении позволяют улучшить взаимодействие пользователя с приложением, а также повысить плавность работы последнего.
Для реализации плавного появления данных в Jetpack Compose доступна функция AnimatedVisibility. AnimatedVisibility предоставляет возможность достаточно просто задать способ появления и исчезновения отображаемого контента.

### Paging

Библиотека, позволяющая выполнять пагинацию большого количества отображаемых данных без необходимости хранения в оперативной памяти информацию обо всех отображаемых объектах. Paging работает на уровне данных, загружая только необходимую на данный момент информацию.
Для отображения данных, которые были получены с помощью Paging, вместо RecyclerView в Jetpack Compose используется LazyColumn или LazyRow (зависит от ориентации отображаемого списка).

### Паттерн-MVI

Паттерн MVI (Model-View-Intent) – архитектурный шаблон проектирования приложения. Состоит из трех компонентов: модели бизнес-логики (Model), представления (View) и намерение (Intent).
MVI реализует архитектурный паттерн UDF, который предполагает использование однонаправленного потока и [хорошо подходит для использования вместе с Jetpack Compose](materials/references.md#jetpack-compose-architecture).

#### Представление (View)

Определяет визуальный интерфейс, через который пользователь взаимодействует с приложением.
Представление передает действия пользователя в модель представления посредством команд.

#### Намерение (Intent)

Передаёт действие пользователя, который намеревается запросить или изменить данные. Каждое намерение проходит полный однонаправленный цикл между всеми компонентами паттерна MVI, представляя собой однонаправленный поток.
Цикл начинается с команды пользователя на запрос или изменение существующих данных. Намерение передаётся в модель бизнес-логики, откуда получает обновленное состояние модели и возвращается в представление, отображая обновленные данные.

#### Модель бизнес-логики (Model)

Описывает используемые в приложении данные. Модели могут содержать логику, непосредственно связанную с этими данными, например, логику валидации свойств модели.
Модель бизнес-логики в MVI обновляет своё состояние, обрабатывая намерения (Intent), которые совершаются над данными.
ViewModel в MVI вместо того, чтобы наблюдать за изменениями в модели и за изменениями в представлении, обрабатывает намерения (Intent) пользователя над данными и обновляет текущее состояние данных в представление.

## Chapter III

# Проект

В этом проекте тебе предстоит разработать и реализовать приложение о сериале Рик и Морти, UI которого будет реализован с помощью библиотеки Jetpack Compose.
Твоя задача — сделать приложение, которое будет поддерживать отображение списка персонажей сериала, с подробной информацией по каждому из них.

## Описание и требования

- Код программы должен находиться в папке src и не противоречить требованиям ниже.
- UI-приложение должно быть создано с применением библиотеки Jetpack Compose.
- В качестве рекомендаций по дизайну можешь использовать [Material 3 Jetpack Compose](materials/references.md#material-3-jetpack-compose).
- Применяй API, позволяющее получать информацию о каком-либо объекте, например, [The Rick and Morty API](https://rickandmortyapi.com/documentation/) или другое подобное API.
- Дизайн приложения должен быть интуитивно понятным.
- Для навигации между Fragment должен быть использован FragmentManager.
- Архитектура приложения должна быть выполнена с использованием паттерна MVI.
- Для сохранения данных при повороте устройства используй преимущества ViewModel.
- MainActivity должна быть единственной Activity в приложении.
- Должен соблюдаться принцип Single Activity: для каждого экрана свой Fragment, отображение всех Fragment в MainActivity.

**Для реализации мобильного приложения нужно использовать:**

- Android Studio 2023.1.1;
- Kotlin 1.9.0;
- Android SDK 34;
- Gradle 8.2 (управление зависимостями);
- Material 3 (создание пользовательского интерфейса).

#### Задание 1. Реализация слоя Intent

1. Реализуй Intent:
   - Создай sealed interface AppIntent, который будет содержать следующие классы-реализации:

     - data class GetCharacterByIdIntent, реализующий интерфейс AppIntent;
   - Класс GetCharacterByIdIntent должен хранить в себе id запрашиваемого персонажа.
2. Реализуй State:
   - Создай sealed interface AppState, который будет содержать следующие классы-реализации:

     - object Loading, реализующий интерфейс AppState;
     - data class Success, реализующий интерфейс AppState;
