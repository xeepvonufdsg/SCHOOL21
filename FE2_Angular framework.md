## Chapter I

### Angular

Angular — фреймворк для проектирования веб-приложений от Google с открытым кодом на основе TypeScript. Первая версия данного фреймворка была выпущена в 2010 году под названием AngularJS, актуальную версию ты можешь узнать в [официальной документации](https://angular.io).

### Устройство фреймворка

#### Компоненты

Angular-приложения состоят из компонентов — обособленных элементов с логикой внутри. [Схема жизненных циклов](https://git.21-school.ru/masters/frontend_project02.ID_1167896/-/blob/10/misc/images/life_cycles_angular_component.png).

#### Модули

Модули Angular NgModules отличаются от модулей JavaScript (ES2015) и дополняют их. NgModule объявляет контекст компиляции для набора компонентов, предназначенных для рабочего процесса. NgModule может связывать свои компоненты со смежным кодом, таким как сервисы, для формирования функциональных единиц.

#### Сервисы и DI (Dependency Injections)

Сервисы нужны для снабжения компонентов данными. Например, это могут быть HTTP-запросы к серверу или функции, которые преобразуют данные по заданному алгоритму. Dependency Injection — широко распространенный паттерн проектирования, который позволяет создавать объект, использующий другие объекты.

#### Темплейты и Директивы

Директивы предназначены для наделения компонента поведением (преобразование DOM).

Шаблон объединяет HTML с разметкой Angular, которая может изменять элементы HTML перед их отображением. Директивы шаблона обеспечивают программную логику, а разметка привязки соединяет данные приложения и DOM.

[Ссылка на официальную документацию](https://angular.io/guide/built-in-directives).

### Angular CLI

Angular CLI — это самый быстрый и удобный способ разработки Angular приложения. Angular CLI позволяет с легкостью выполнять следующие задачи:

- `ng build` — компилирует приложение Angular в выходной каталог;
- `ng serve` — собирает и обслуживает приложение, перестраивая его при изменении файлов;
- `ng generate` — генерирует или изменяет файлы на основе схемы;
- `ng test` — выполняет модульные тесты для данного проекта.

[Ссылка на документацию](https://github.com/angular/angular-cli).

### Введение в реактивность

Реактивная парадигма программирования включает написание программного кода, основанного на асинхронных потоках данных и распространении изменений. Немного запутано, так что давай разберемся на [примерах](https://git.21-school.ru/masters/frontend_project02.ID_1167896/-/blob/10/./materials/angular_reactive_rxjs.md) с помощью библиотеки Rxjs.

### Сравнение с React

- В отличие от React, Angular представляет собой полноценный фреймворк для разработки приложения. Следовательно, имеет строгое представление о том, как должно быть структурировано приложение, а также имеет множество небольших встроенных библиотек, которые помогают создавать сложные приложения.
- Язык разработки — TypeScript.
- Модель привязки данных в Angular является двунаправленной, что означает двусторонний поток данных между моделью и представлением. В отличие от ReactJS, Angular автоматически синхронизирует модель и представление, когда вносится изменение в состояние модели и/или пользовательский интерфейс.
- Еще одной особенностью является то, что Angular взаимодействует с обычным DOM, который, в отличие от виртуального DOM React, не определяет автоматически изменения в файле, чтобы обновить вновь внесенные изменения. Вместо этого он обновляет всю структуру HTML каждый раз, когда вносится изменение.
- Для большинства разработчиков Angular является более тяжелым в освоении и изучении.
- В отличие от JSX, который позволяет нам писать JS-код в HTML-разметке в React, в Angular темплейты разрабатываются на чистом HTML с использованием встроенных директив. Также в нем присутствует удобная интеграция с RxJS — библиотекой, которая использует наблюдаемые объекты для реактивного программирования.

### Project\_01

- Тебе потребуется разработать приложение для бронирования номеров в отеле.
  Приложение будет состоять из 5 страниц:

  - [Главная страница](https://git.21-school.ru/masters/frontend_project02.ID_1167896/-/blob/10/misc/images/home_page.png);
  - [Страница с контактами](https://git.21-school.ru/masters/frontend_project02.ID_1167896/-/blob/10/misc/images/contact_page.png);
  - [Блог об отеле](https://git.21-school.ru/masters/frontend_project02.ID_1167896/-/blob/10/misc/images/about_us_page.png);
  - [Страница с номерами](https://git.21-school.ru/masters/frontend_project02.ID_1167896/-/blob/10/misc/images/rooms_page.png);
  - [Подробная страница номера](https://git.21-school.ru/masters/frontend_project02.ID_1167896/-/blob/10/misc/images/room_page.png).
  1. **Главная страница.** На данной странице расположены 3 блока:

     - Блок бронирования. Представляет собой простую форму, где надо заполнять даты бронирования, количество проживающих и количество комнат. После клика на кнопку «Check available» происходит редирект на страницу ROOMS, где пользователю будут отображены доступные для него типы номеров.
     - Блок с краткой информацией об отеле и ссылка на более подробную информацию (на страницу about\_us).
     - Карусель с краткой информацией по каждому типу номеров (тебе нужно придумать минимум 5 типов номеров).
  2. **Страница с типами номеров.** Если пользователь переходит на эту страницу сам (не заполняя форму для бронирования), то на ней выводятся все существующие типы номеров с краткой информацией и ссылкой на страницу номера.
  3. **Страница номера.** На данной странице есть подробная информация и изображения номера, а также форма бронирования. После заполнения формы пользователь нажимает на кнопку и, если номер доступен для бронирования, видит сообщение об успешном бронировании. В противном случае пользователю показывается всплывающее сообщение о том, что номер недоступен для бронирования в текущие даты.
  4. **Страница с контактами.** На данной странице указаны контакты и карта с геотегом отеля (адрес можно указать произвольный).
  5. **Страница с информацией об отеле.** На данной странице указана информация об отеле и карусель с фотографиями всех типов номеров.
- Все типы для TypeScript должны быть описаны. Использовать `any` запрещено.
- Верстка должна выглядеть корректно на разрешениях от 1000px до 1920px.
- На макетах ты можешь увидеть navbar, он служит для сквозной навигации по приложению. С его помощью пользователь может перемещаться по страницам приложения. Для реализации можно использовать RouterModule из @angular/router.
