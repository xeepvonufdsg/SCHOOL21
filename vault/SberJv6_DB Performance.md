## Введение

БД можно назвать сердцем приложения.

Почему? Потому что данные, сохраненные в БД, живут очень долго. Вероятнее всего, они переживут само приложение, пусть и измененном (агрегированном) виде.

Именно поэтому завершающий проект программы SberJava именно о работе с базами данных.

У большинства микросервисов есть своя база данных. В самом определении микросервиса заложено, что у него должна быть отдельная БД.

Но почему у “большинства”, а не “у всех”?

В Сбере все микросервисы делятся на два слоя:

- middleware (ЕФС) - не имеют своей БД, т.к не должны хранить клиентские данные.
- backend (ППРБ).

**Классы БД:**

- Реляционные (в основном данные хранятся в реляционных БД)
- noSQL (получают все более широкое распространение)

Реляционные базы данных развивались десятилетиями. С момента выхода Oracle DB в 1979 году базы прошли множество оптимизаций и научились эффективно работать с большими объемами данных. Тем не менее их все равно нужно уметь правильно настраивать.

В крупных компаниях, таких как Сбер, есть команды DBA - администраторов баз данных, которые помогают с настройкой производительности. Но их мало, поэтому базовые настройки разработчик должен делать самостоятельно.

В этом проекте на примере сервиса Spring Boot для работы с геоданными ты отточишь навык работы с базой данных, а именно:

1. JPA entity mapping и fetch type
2. Решение проблемы N+1
3. Кэширования JPA
4. JPA batching
5. Выбор границы транзакций
6. Оптимистичная блокировка
7. Stream в Spring Data JPA
8. Native SQL в JPA
9. Основы оптимизации SQL запросов
10. План выполнения запроса
11. Создание индекса
12. Партиционирование таблиц

Чтобы успешно выполнить проект, будет полезно иметь базовые знания о том, как работают JPA и Spring Data JPA.

## Задание 3. Кэширование JPA

## Задание 5. Выбор границы транзакций

Транзакция в БД - последовательность операций, выполняемых атомарно. Т.е по принципу "все или ничего". Транзакции должны удовлетворять принципу ACID. В Spring Data JPA есть удобный декларативный механизм управления транзакциями с помощью аннотаций, который позволяет легко задавать границы транзакции.

В итоге, работа с транзакциями внутри одной БД реализуются просто, и этой возможностью нужно пользоваться.

Ключевой вопрос здесь - как правильно настроить границы транзакции?
