## Chapter I

### Что такое WebSocket

Наверняка ты пользовался HTTP-протоколом передачи гипертекстовых данных. [Схема HTTP запросов](https://git.21-school.ru/masters/frontend_project06.ID_1167903/-/blob/9/./materials/HTTP_communication.png).

Также Ajax — асинхронные запросы с помощью JavaScript. [Схема Ajax запросов](https://git.21-school.ru/masters/frontend_project06.ID_1167903/-/blob/9/./materials/Ajax_communication.png).

Вышеперечисленные запросы работают в формате запрос-ответ. Что дальше происходит с сервером, нам неизвестно.

Протокол WebSocket, описанный в [спецификации RFC 6455](https://datatracker.ietf.org/doc/html/rfc6455), предоставляет собой способ обмена данными между браузером и сервером через постоянное соединение. Данные могут передаваться в обоих направлениях в виде «пакетов», без разрыва соединения и необходимости дополнительных HTTP-запросов.

### Схема работы

Процесс установки WebSocket соединения:

- Клиент посылает обычный HTTP-запрос через TCP/IP на сервер. В запрос включается заголовок «upgrade», который информирует сервер о том, что клиент хочет установить WebSocket-соединение.
- Если сервер поддерживает протокол WebSocket, он выполняет «обновление» для завершения процесса рукопожатия. Это «обновление» заменит первоначальное HTTP-соединение на WebSocket-соединение, которое использует ту же концепцию TCP/IP.
- После установки websocket-соединения клиент и сервер могут начать отправлять сообщения от сервера к клиенту и обратно.

Чтобы сервер знал, что мы до сих пор подключены, он периодически присылает ответ с просьбой о действии — послать запрос на сервер. Таким образом, если запрос был послан по истечении тайм-аута — пользователь считается подключенным.

[Схема WebSocket запросов](https://git.21-school.ru/masters/frontend_project06.ID_1167903/-/blob/9/./materials/websoket_communication.png).

### Когда стоит использовать

- трейдерские приложения,
- игровые приложения,
- чаты,
- социальные сети,
- управление IoT.

WebSocket подходит для этих проектов лучше всего, так как в них клиент может не выполнять на своей стороне никаких вычислений, а лишь получать/передавать данные на сервер.

WebSocket можно использовать для повышения скорости работы приложения. Но не стоит использовать этот протокол в случаях, когда мы хотим получать старые или неизменные данные, или необходимо загрузить данные лишь один раз.

### Особенности WebSocket

URL WebSockets используют схему ws вместо HTTP и wss вместо HTTPS.

Поток данных в WebSocket состоит из «фреймов», фрагментов данных, которые могут быть отправлены любой стороной.

**О плюсах WebSocket:**

- Поддерживает двусторонний обмен данными: может одновременно получать и передавать информацию.
- Отправляет данные быстрее, чем HTTP.
- Кроссплатформенная совместимость.
- HTTP требует до 2000 байтов накладных расходов, тогда как веб-сокет — всего 2 байта.
- Кратковременное отсутствие связи не прерывает соединение. Если интернет будет работать нестабильно, клиенту и серверу не придётся заново устанавливать WebSocket-соединения, они смогут продолжить обмениваться данными в обычном режиме, пока связь не восстановится.
- Протокол позволяет работать в асинхронном режиме. Так, у клиента и сервера равноправные роли в процессе обмена данными, и они действуют автономно.

**О минусах:**

- Высокие требования к серверному оборудованию.
- При отправке пакета в WebSocket ты не узнаешь о том, доставлен ли он или нет, пока не пройдет время таймаута — по умолчанию 75 секунд. Зачастую приходится вводить дополнительные механизмы общения между клиентом и сервером, чтобы быстро понять, отвечает ли клиент.
- Смена сети клиентом. Бывают ситуации, когда клиент находится в дороге и меняется сеть, в которой находится устройство. В таких случаях сервер ничего не знает о смене адреса, если клиент не закрыл соединение при переподключении к другой сети.

### Project\_01

Тебе с командой предстоит реализовать проект, аналогичный Zoom:

- На главной странице пользователь видит поле для ввода ID комнаты и кнопку для создания комнаты.
- После создания комнаты пользователь может скопировать ссылку из URL и отправить ее любому другому юзеру.
- При переходе по прямой ссылке пользователь сразу переходит на страницу комнаты и видит всплывающее окно для ввода никнейма.
- В поле для ввода никнейма есть чекбокс с надписью «Запомнить никнейм». Если при вводе никнейма отметить это поле, то при последующем переходе в любую комнату никнейм вводить не потребуется.
- После ввода всплывающее окно пропадает, и юзер видит перед собой всех участников, кто находится в данный момент в комнате.
- В первой версии приложения команде требуется реализовать поддержку голосового и текстового чата.
- **Важно!** Напиши инструкцию по запуску сервера в [файле](https://git.21-school.ru/masters/frontend_project06.ID_1167903/-/blob/9/./src/instructions.md) `instructions.md`, чтобы у проверяющих не возникло вопросов в ходе проверки твоего задания.

- Верстка должна выглядеть корректно на разрешениях от 1000px до 1920px.
