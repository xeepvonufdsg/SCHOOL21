## Chapter II

## Общая информация

### Токен, сессионный токен, токен обновления

**Токен** является уникальной последовательностью символов и заменяет собой логин и пароль пользователя для предотвращения утечек конфиденциальной информации. Токены имеют определенное время действия, по истечении которого перестают работать.

**Сессионный токен** предоставляет пользователю права на выполнение доступных ему действий в течение сессии. Является многоразовым и имеет короткий срок действия.

**Токен обновления** продлевает срок действия сессионного токена. Является одноразовым и имеет длительный срок действия.

## Chapter III

### Проект: Крестики-Нолики

Тебе предстоит улучшить клиентское мобильное приложение для игры «Крестики-Нолики» с использованием паттерна MVVM. В приложение будет добавлено:

- jwt-авторизация;
- автоматическая авторизация;
- отображение истории игр;
- отображение таблицы лидеров;
- сохранение полученной информации в базу данных.

Используй проект для мобильного приложения с предыдущей недели Т04.

## Задание 1. Добавление поддержки jwt-авторизации

- Опиши в API добавленные endpoint'ы для jwt-авторизации в Т05.
- Добавь необходимые модели для этих endpoint'ов.
- Добавь поддержку нового API для сервиса.
- Добавь поддержку обновленного сервиса для репозитория авторизации и регистрации.
- Измени логику авторизации при нажатии на кнопку авторизации при помощи пары логина и пароля:
  - При ошибке валидации логина и пароля должно появиться всплывающее уведомление.
  - Если валидация пройдена успешно, то должен отправиться запрос авторизации на сервер.
  - При ошибке авторизации должно появиться всплывающее уведомление с причиной.
  - Если авторизация пройдена успешно, токены и информация о пользователе должны сохраниться в базу данных, а также должен произойти переход на экран существующих игр.
- Измени логику работы существующего Interceptor:
  - В заголовок Authorization запиши "Bearer accessToken".
  - Токен нужно получать из базы данных.
- Работа с токенами:
  - Если в ответ на запрос пришел код 401, то нужно запросить новую пару токенов с помощью refreshToken и сохранить их в базу данных.
  - Если получение новых токенов прошло успешно, то должен повториться запрос.
  - Если новые токены не удалось получить или не выполнился повторный запрос, то необходимо показать всплывающее уведомление и перейти на экран авторизации.
  - Создай класс JwtUtil, у которого есть метод для проверки время жизни токена.
  - Если время действия accessToken истекло, то должны запроситься новые токены с использованием refreshToken.
  - Если новые токены удалось получить, то их нужно сохранить в базу данных.
  - Если новые токены не получены, то необходимо показать всплывающее уведомление и перейти на экран авторизации.
- На каждом слое должны быть свои модели.
- Операции отправки данных на сервер и получения данных с сервера должны выполняться асинхронно и не блокировать главный поток.
- Операции сохранения данных должны выполняться асинхронно и не блокировать главный поток.
