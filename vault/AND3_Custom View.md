## Chapter I

# UI компоненты

### Паттерн MVVM

Паттерн MVVM (Model-View-ViewModel) — архитектурный шаблон проектирования приложения. Состоит из трех компонентов: модели бизнес-логики (Model), модели представления (ViewModel) и представления (View).
Механизм привязки данных (bindings) обеспечивает связь между компонентами View и ViewModel.

#### Модель бизнес-логики

Описывает используемые в приложении данные. Модели могут содержать логику, непосредственно связанную с этими данными, например, логику валидации свойств модели. В то же время модель не должна содержать никакой логики, связанной с отображением данных и взаимодействием с визуальными элементами управления.

#### Представление

Определяет визуальный интерфейс, через который пользователь взаимодействует с приложением.
Представление передает действия пользователя в модель представления посредством команд.

#### Модель представления

Связывает представление и модель бизнес-логики через механизм привязки данных. Если в модели бизнес-логики изменяются значения свойств, то автоматически происходит изменение отображаемых данных в представлении, хотя напрямую модель бизнес-логики и представление не связаны.

Содержит логику по получению данных из модели бизнес-логики, которые потом передаются в представление. Модель представления определяет логику по обновлению данных в модели бизнес-логики.

Визуальные компоненты, например, поле ввода, не используют события, а представление взаимодействует с моделью представления посредством команд. Например, пользователь хочет сохранить введенные в текстовое поле данные. Он нажимает на кнопку и тем самым отправляет команду в модель представления. А модель представления уже получает переданные данные и в соответствии с ними обновляет модель.

### MotionEvent

Класс, описывающий взаимодействия пользователя с экраном устройства. MotionEvent способен отслеживать время нажатия на экран, вектор перемещения, нажатия на экран и т. п.

### View

Базовый класс для виджетов, которые используются для создания интерактивных UI компонентов.

Определяет прямоугольную область на экране и ответственен за обработку событий и отрисовывание данного компонента.

### ViewGroup

Базовый класс для макетов, представляющих собой невидимые контейнеры, которые хранят виджеты и определяют их некоторые свойства (например, размер, цвет и т. д.).

### RecyclerView

Класс представления, который реализует отображение элементов заданного списка. Разработчик может определить, как должен отображаться каждый элемент и передать эти элементы RecyclerView, который будет динамически создавать необходимые элементы.

Главное преимущество RecyclerView над обычным списком (например, ListView) заключается в том, что он не создаёт отдельное представление для каждого хранимого элемента, а «переиспользует» уже созданные представления для отображения элементов, которые помещаются на экран. Благодаря данной особенности RecyclerView может хранить огромное количество элементов, не снижая производительности приложения.

### Layout

Макет/разметка, определяющий свойства отображения виджетов, которые он хранит. Размечает собой область экрана, на которой будут отрисованы соответствующие данному макету виджеты.

### AndroidX Preference

Библиотека, позволяющая создавать интерактивные настройки экрана без необходимости взаимодействия с внутренним хранилищем или UI-настройками устройства.

## Chapter II

# Проект приложение мини-игр

В этом проекте тебе предстоит разработать и реализовать приложение мини-игр с использованием паттерна MVVM. Твоя задача — сделать приложение, которое будет поддерживать отображение списка доступных мини-игр, возможность выбора мини-игры из представленного списка, выбора темы приложения, настройки цвета кнопок, настройки цвета и размера текста.

## Описание и требования

- Код программы должен находиться в папке src и не противоречить требованиям ниже.
- В качестве рекомендаций по дизайну ты можешь использовать [Material 3](https://m3.material.io/develop/android).
- Дизайн приложения должен быть интуитивно понятным.
- Для навигации между Fragment должен быть использован FragmentManager.
- Для сохранения данных при повороте устройства используй преимущества ViewModel.
- Обеспечь взаимодействие с View экранов при помощи ViewBinding.
- MainActivity должна быть единственной Activity в приложении.
- Соблюдай принцип Single Activity: для каждого экрана свой Fragment, отображение всех Fragment в MainActivity.

**Для реализации мобильного приложения нужно использовать:**

- Android Studio 2023.1.1;
- Kotlin 1.9.0;
- Android SDK 34;
- Gradle 8.2 (управление зависимостями);
- Material 3 (создание пользовательского интерфейса).
