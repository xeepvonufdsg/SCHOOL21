## Chapter II

### Введение

Сетевое взаимодействие в разработке под iOS играет ключевую роль, позволяя приложениям обмениваться данными с удаленными серверами. Это необходимо для загрузки контента, обновления информации, аутентификации пользователей и других важных задач. Основы сетевого взаимодействия включают в себя несколько ключевых концепций:

1. **HTTP и HTTPS:**
   - **HTTP (Hypertext Transfer Protocol)** — протокол передачи данных, используемый для обмена информацией между клиентом (например, мобильным устройством) и сервером.
   - **HTTPS (Hypertext Transfer Protocol Secure)** — защищенная версия HTTP, использующая шифрование для обеспечения безопасности данных.
2. **REST (Representational State Transfer):**
   - REST — архитектурный стиль, основанный на принципах, управляемых ресурсами через стандартные методы HTTP (GET, POST, PUT, DELETE). RESTful API обеспечивает структурированный и удобный способ взаимодействия клиента и сервера.
3. **JSON (JavaScript Object Notation):**
   - JSON — легкий формат обмена данными, основанный на синтаксисе JavaScript. В iOS разработке JSON широко используется для передачи структурированных данных между клиентским и серверным приложением.
4. **NSURLSession (или URLSession):**
   - Класс [URLSession](https://developer.apple.com/documentation/foundation/urlsession) в iOS предоставляет возможности для работы с сетевыми запросами. Он поддерживает асинхронные операции и обеспечивает удобный интерфейс для отправки HTTP-запросов и обработки ответов.
5. **Асинхронное выполнение:**
   - Сетевые запросы выполняются асинхронно, чтобы избежать блокировки пользовательского интерфейса при ожидании ответа от сервера. Callbacks, блоки, или замыкания используются для обработки результатов запросов.
6. **Обработка ошибок и безопасность:**
   - Важно обрабатывать ошибки, возникающие в процессе сетевого взаимодействия. Также при работе с сетью следует уделять внимание вопросам безопасности, включая обеспечение конфиденциальности данных и защиту от атак.

До выхода iOS 7 управлять сетевыми взаимодействиями в мобильном приложении было достаточно сложно. Вся работа осуществлялась с помощью класса [NSURLConnection](https://developer.apple.com/documentation/foundation/nsurlconnection), функционал которого был существенно ограничен. Например, можно было потерять все полученные данные при переходе в background-mode, а пробрасывать конфигурации или управлять сразу несколькими загрузками было очень неудобно.

Не дожидаясь решения от Apple, сообщество разработчиков реализовало собственную библиотеку [AFNetworking](https://github.com/AFNetworking/AFNetworking) (позже [Alamofire](https://github.com/Alamofire/Alamofire)), которая лежит в открытом доступе.

После выхода iOS 7 Apple выпустила [URLSession](https://developer.apple.com/documentation/foundation/urlsession), которая сделала взаимодействие с сетью более простым и удобным и избавила от необходимости использовать сторонние библиотеки.

> Важно понимать, что в настоящее время фреймворк [Alamofire](https://github.com/Alamofire/Alamofire) основан на [URLSession](https://developer.apple.com/documentation/foundation/urlsession). Поэтому, прежде чем подключать стороннюю библиотеку, стоит разобраться, как работает нативное решение.

## Chapter IV

## Задачи

Тебе необходимо написать собственный сетевой клиент (VKAPIClient) для работы с [API VKontakte](https://dev.vk.com/ru/api/getting-started).

**Общие требования:**

- Не используй сторонние библиотеки.
- Сетевой клиент по работе с API VK назвать VKAPIClient
- Для работы с сетью применяй [URLSession](https://developer.apple.com/documentation/foundation/urlsession).
- Сетевой слой должен существовать отдельно от UI.
- Сетевые запросы не должны «останавливать» главный поток и тормозить UI.
- При написании асинхронных функций используй механизм async await.
- При парсинге данных пользуйся [Codable](https://developer.apple.com/documentation/swift/codable).
- Приложение должно быть устойчиво к неожиданному поведению сервера и не должно «падать», если на сервере что-то пошло не так.
- Замени методы файла MockService.swift на новые из VKAPIClient (в конце задания MockService нужно удалить).

### Task I: Авторизация пользователя

- Реализуй флоу авторизации пользователя.
- Добавь в VKAPIClient метод получение access token.
- Авторизация не должна слетать при закрытии приложения.
- Деавторизуй пользователя при получении с сервера ошибки авторизации (например, когда истекло время жизни токена).

**Комментарии:**

- Можешь использовать любой из методов авторизации (VK ID или OAuth VKontakte) на свое усмотрение.
- Токен можно хранить в любом месте (безопасное хранение данных будет рассмотрено в следующих уроках).

### Task II: Получение постов в ленте

### Task III: Получение списка друзей
