## Chapter I

### Введение в тестирование

Тестирование — это обзор того, как будет выполняться код. Набор тестов для приложения включает в себя различный код, позволяющий проверить, работает ли твое приложение согласно ожиданиям. Тестирование делает приложение более надежным и менее подверженным ошибкам.

На что стоит обратить внимание при тестировании фронтенда:

- Кроссбраузерность и кроссплатформенность.
- Доступность.
- Сквозные проверки — необходимы для проверки и подтверждения рабочего процесса приложения путем имитации реальных действий, которые, вероятно, будут выполнять пользователи.
- Тестирование анализа изображений.
- Тестирование каскадных таблиц стилей (CSS).

### Виды тестирования

- Unit тестирование — это тестирование логики инкапсулированного компонента.
- Интеграционное тестирование — проверка взаимодействия созданного модуля с другими (например, при добавлении новой или изменении текущей логики).
- End-to-End (E2E) тестирование — проверка работы всего приложения или фактически описанных бизнес-кейсов (поведение пользователя).

Два наиболее популярных инструмента для выполнения End-to-End тестов — это Nightwatch и Cypress.

Недостатком Cypress является то, что он использует встроенную версию браузера Chromium. Тесты будут действительны только для браузеров на базе Chromium, таких как Google Chrome, Microsoft Edge и Brave. Такие браузеры, как Firefox и Opera, придется тестировать вручную.

### Enzyme

Enzyme — это библиотека, которая используется для тестирования React-приложений. Она предназначена для тестирования компонентов и позволяет писать предположения, имитирующие действия, которые подтверждают, работает ли пользовательский интерфейс правильно или нет. Enzyme рендерит компонент в памяти, а затем предоставляет ряд API для изучения свойств компонента.

### Jasmine и Karma

Jasmine — это фреймворк для тестирования JavaScript, который поддерживает практику разработки программного обеспечения под названием Behaviour-Driven Development, или сокращенно BDD. Это специфическая разновидность Test-Driven Development (TDD).

Jasmine, как и BDD в целом, пытается описать тесты в человекочитаемом формате, чтобы нетехнические люди могли понять, что тестируется. Однако даже если ты являешься техническим специалистом, чтение тестов в формате BDD значительно облегчает понимание происходящего.

Karma — это инструмент, который позволяет нам порождать браузеры и запускать в них тесты Jasmine из командной строки. Результаты тестов также отображаются в командной строке.

Karma также может следить за изменениями в файлах твоей разработки и автоматически запускать тесты заново.

Karma позволяет запускать тесты Jasmine как часть цепочки инструментов разработки, которая требует, чтобы тесты можно было запускать и проверять результаты через командную строку.

При создании проектов Angular с помощью Angular CLI он по умолчанию создает и запускает модульные тесты с помощью Jasmine и Karma.

### Jest

Jest — это фреймворк модульного тестирования JavaScript, используемый компанией Facebook для тестирования сервисов и приложений React. Основной способ, которым Jest делает это, — использование моментальных снимков. Снапшот Jest — это сохраненный фрагмент HTML, сгенерированный твоим приложением. Разработчики генерируют эти снимки перед написанием тестов путем рендеринга компонентов и сохранения их HTML с помощью jest snapshot.

При тестировании с помощью моментальных снимков вывод текущего теста сравнивается с моментальным снимком предыдущего теста. Если результат совпадает с моментальным снимком, тест проходит.

Jest и Enzyme хорошо дополняют друг друга.

### Mocha

Mocha — фреймворк для тестирования JavaScript, который фокусируется на гибкости. Благодаря ей можно выбирать различные библиотеки для выполнения общих функций, таких как spying (например, Sinon) или assertions (например, Chai). Другая уникальная особенность Mocha в том, что она позволяет выполнять тесты как в браузере, так и в Node.js.

### Eslint

ESLint — это утилита, которая может анализировать написанный код. Фактически это статический анализатор кода. Он сообщает о потенциально опасных выражениях в коде, которые могут привести к аварийному завершению программы. Также линтер может сообщить об устаревших участках кода, синтаксических ошибках и неиспользованных переменных.

[Пример](https://git.21-school.ru/masters/frontend_project07.ID_1167904/-/blob/9/./materials/eslint.md).

### Prettier

На большом проекте, как правило, работает несколько программистов. У каждого из них может быть свое мнение относительно качества кода и размера отступов в строке. Eslint может форматировать текст, но требует дополнительной кропотливой настройки. Облегчить задачу призвана утилита Prettier. Большая часть правил оформления уже задана по умолчанию, но у пакета есть гибкая система настройки и удобный API, позволяющий описывать свои правила в конфигурационном файле формата .json/.yml. Это значит, что мы можем написать файл с едиными настройками для всей команды.

[Пример](https://git.21-school.ru/masters/frontend_project07.ID_1167904/-/blob/9/./materials/prettier.md).

### Git hooks

Git hooks — это скрипты, которые автоматически запускаются каждый раз, когда в репозитории Git происходит определенное событие. Они позволяют настраивать внутреннее поведение Git'а и вызывать настраиваемые действия в ключевых точках жизненного цикла разработки.

В качестве событий могут выступать commit, apply patch, merge, push, rebase и другие операции Git.

Для написания хуков советуем почитать про husky.

### Project\_01

- Тебе предстоит реализовать проект для отслеживания трат на разные категории продуктов.
- После авторизации/регистрации пользователь попадает на главную страницу. На ней отображены категории товаров, куда пользователь может записать свои траты.\
  Список категорий:
  - Еда вне дома,
  - Продукты,
  - Расходы на машину,
  - Развлечения,
  - Покупки,
  - Транспорт,
  - Путешествия,
  - Подарки,
  - Услуги,
  - Финансовая подушка.
- Под таблицей категорий расположена кнопка «Внести расходы». При клике на нее открывается модальное окно с формой для заполнения.\
  Поля формы:
  - дата (date input),
  - сумма (number input),
  - категория (select из существующих категорий),
  - кнопки «Сохранить» и «Отменить».
- При клике на какую-либо категорию открывается страница этой категории, где пользователь может видеть список всех трат, которые вносил, сгруппированные по дате. А также указание с суммой трат за текущий календарный месяц.
- Верстка должна выглядеть корректно на разрешениях от 1000px до 1920px.
- В этом проекте тебе потребуется настроить eslint и prettier конфиг, а также написать конфиг для husky hook6, который не будет позволять закоммитить при ошибке eslint.
- Минимальный набор правил для eslint:
  1. Ширина строки 120.
  2. Ширина таба = 4 пробела.
  3. Используются одинарные кавычки.
  4. При использовании одного аргумента в callback его не надо оборачивать в круглые скобки.
  5. Печатай конечные запятые везде, где это возможно (большие объекты/массивы на несколько строк).
