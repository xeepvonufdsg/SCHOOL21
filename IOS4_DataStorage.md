## Chapter II

### Введение

Хранение данных является важной частью любого мобильного приложения. В мобильной разработке быстродействие и автономность являются намного более критичными факторами, чем в той же самой web-разработке.

Мобильное устройство обладает ограниченным аккумулятором, часто может отсутствовать интернет-соединение, и все эти нюансы нужно учитывать при разработке мобильных приложений.

Именно поэтому в мобильной разработке достаточно сильно развиты механизмы хранения данных. На iOS можно напрямую работать с реляционными базами данных, например, SQLite, но чтобы облегчить работу с БД разработчикам и предоставить им привычный подход по работе с данными, компания Apple разработала фреймворк CoreData (а позднее добавила к нему [SwiftData](https://developer.apple.com/xcode/swiftdata/)), который является объектно-ориентированной оберткой над различными хранилищами данных.

## Chapter III

### Core Data

[Core Data](https://developer.apple.com/documentation/coredata/) — это фреймворк от Apple для управления моделью данных в приложениях для iOS и macOS. Он помогает разработчикам не думать о том, с какой базой данных они работают, вводя более высокий уровень абстракции и скрывая особенности работы той или иной БД. Из коробки CoreData поддерживает несколько типов хранилищ: SQLite, In-memory, XML, Binary.

Основные концепции CoreData:

- **Модель данных (Data Model):** Core Data использует модель данных для определения структуры хранимых данных. Модель данных создается в Xcode с использованием файла .xcdatamodeld, в котором разработчик может определить сущности, их атрибуты и отношения между ними.
- **Сущности (Entities):** Сущности в Core Data похожи на таблицы в реляционной базе данных. Каждая сущность — это тип объекта, который мы хотим сохранить, например, «Пользователь» или «Заказ».
- **Атрибуты (Attributes):** Атрибуты — это данные, которые сохраняются в каждом экземпляре сущности. Например, сущность «Пользователь» может иметь атрибуты «имя», «фамилия» и «email».
- **Отношения (Relationships):** Отношения используются для моделирования связей между различными сущностями. Например, пользователь может иметь несколько заказов, что представляет отношения «один ко многим».
- **Core Data Stack:** Комбинация различных компонентов Core Data, включающая модель данных, контекст управления объектами и координатор постоянного хранения.
- **NSManagedObject:** Класс, экземпляры которого представляют сущности. Обычно для каждой сущности в моделях данных создаются подклассы NSManagedObject.
- **NSManagedObjectContext:** Класс, управляющий объектами, которые нужно сохранить или которые уже сохранены в базе данных. Он действует как буфер между объектами в твоем приложении и базой данных.

1. **NSPersistentStoreCoordinator:** Компонент, отвечающий за хранение данных. Он связывает твою модель данных с физической базой данных на диске.
2. **Запросы (Fetch Requests):** Запросы используются для получения данных из существующей базы данных. Можно фильтровать и сортировать результаты запросов, используя NSPredicate и NSSortdescriptor.

## Chapter IV

### DAO

[DAO](https://en.wikipedia.org/wiki/Data_access_object) (Data Access Object) — паттерн проектирования, используемый в мобильной разработке и не только, для абстрагирования и инкапсуляции всех доступов к источнику данных. Этот паттерн предоставляет единый интерфейс для доступа к данным, скрывая детали работы с базой данных или любым другим механизмом хранения данных.

В контексте мобильной разработки, особенно в приложениях на платформах, таких как Android и iOS, DAO играет важную роль в управлении данными и взаимодействии с локальными базами данных, например, с [Core Data](https://developer.apple.com/documentation/coredata/), [SQLite](https://www.sqlite.org/index.html) или [Realm](https://realm.io).

Основные аспекты и преимущества использования DAO в мобильной разработке:

1. **Инкапсуляция доступа к данным**: DAO скрывает сложность доступа к данным от остальной части приложения. Это значит, что изменения в способе хранения или извлечения данных не затрагивают бизнес-логику приложения.
2. **Унификация интерфейса**: DAO предоставляет стандартизированный способ взаимодействия с данными, что упрощает тестирование и поддержку кода.
3. **Уменьшение дублирования кода**: Через использование DAO можно минимизировать дублирование кода, связанного с операциями по работе с данными.
4. **Облегчение тестирования**: Так как DAO отделяет логику доступа к данным от остальной части приложения, это облегчает написание модульных тестов.
5. **Поддержка различных источников данных**: DAO может быть настроен для работы с разными источниками данных (например, разными типами баз данных), что увеличивает гибкость приложения.

### Общие требования:

- Не используй сторонние библиотеки.
- Для кэширования применяй [CoreData](https://developer.apple.com/documentation/coredata/) (SQLite).

- Если отсутствует соединение с Интернетом, то данные должны загружаться из кэша.
- Слой для работы с БД должен существовать отдельно от UI.
- Запросы в БД не должны «останавливать» главный поток и тормозить UI.
- При написании асинхронных функций используй механизм async await.
